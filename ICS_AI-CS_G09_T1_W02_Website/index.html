Explanation and examples

An AI system is not a single box but a set of interacting components. Data is the examples a model learned from; the tool applies those learned patterns; the prompt or input steers what the tool does on this occasion. An output emerges from how these parts interact - change the data and the tool behaves differently, change the prompt and the same tool returns a different result. Analysing a system means tracing this interaction: reasoning about which component shaped an outcome and how one stage constrains the next. For Grade 9 designers this is foundational. You cannot design, govern or improve a workflow until you can see its components, follow how an input propagates through them, and justify why a particular output appeared rather than another. Naming the stages is not enough; the skill is reasoning about their interaction. The interacting components inside one worked example.

Source activity

Hands-on activity guide Overview: Students investigate three teacher-provided worked examples, map how each input becomes an output, analyse which components interacted to produce it, and explain the reasoning to a partner. Grouping / timing: Pairs for the investigate and explain; whole class for the debrief. Tool: A teacher-operated board demo with a curated, pre-generated set of example inputs and outputs - no accounts and no live typing by students - so the class analyses safe, prepared results and no personal data is ever entered into any tool. Facilitation steps: 1. Study the worked example your teacher shows on the board. 2. Write down the input - the exact data that went in - and the output - the exact result that came out. 3. Name the components that sat between them: the data the tool learned from, the tool, and the prompt. 4. Draw arrows to show how one component fed the next until the output appeared. 5. Explain to your partner how the components interacted to turn that input into that output. 6. Check one output against the task and a trusted source - does it really answer it? Unplugged fallback: Simulated-AI cards: a 'data' card sets what the tool has learned, a 'tool' envelope holds a fixed rule, and a 'prompt' card is the instruction. A student feeds an input card through the three components and the envelope returns the matching output card - the same interacting system with no device and no accounts.
